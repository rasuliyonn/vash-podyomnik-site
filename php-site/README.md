# «Ваш Подъёмник» — PHP-версия сайта

Полноценная PHP 8.x версия сайта для обычного shared-хостинга (Apache + PHP + SQLite).
Оригинал (Next.js/vinext) лежит рядом в репозитории — не удалён, выбираете, что в проде.

## Что внутри

- Публичные страницы: главная, каталог оборудования, 5 карточек оборудования,
  «Наши работы» (71 фото), «Вопросы и ответы» (28 вопросов), блог (16 статей),
  «О компании», «Контакты», «Расчёт стоимости», privacy, terms, 404.
- SEO/GEO: мета-теги и canonical на каждую страницу, JSON-LD (Organization + LocalBusiness,
  WebSite, BreadcrumbList, FAQPage, Article, Service, ItemList, ImageGallery),
  `sitemap.xml` (генерируется), `robots.txt` с явными правилами для ответных ИИ-краулеров,
  `llms.txt`, OG-обложка, RSS блог (`/blog/rss.xml`).
- Форма заявки → SQLite `data/site.sqlite` (таблица `form_submissions`) +
  копирование текста заявки в буфер (работает и без JS).
- Админка `/admin`: заявки (статусы), оборудование (тексты, хар-ки, фото, документы),
  работы (галерея, загрузка/удаление/импорт 71 файла), смена пароля.
- Портфолио: при первом обращении `works_images` автозаполняется файлами `works/work-*.jpg`.

## Требования

- PHP **8.0+** с расширениями: `pdo_sqlite`, `sqlite3`, `mbstring`, `fileinfo`, `json`
- Apache с `mod_rewrite`, `mod_headers`, `mod_expires`/`mod_deflate` (желательно)
- Каталог `data/` — доступен на запись (там создаётся `site.sqlite`)
- Каталог `uploads/` — доступен на запись (сюда попадают файлы из админки)

## Установка на shared-хостинг (FTM/FTP)

1. Залейте **содержимое** папки `php-site/` в корень сайта (обычно `public_html/` или `www/`).
   Не заливайте сам каталог `php-site`, только файлы внутри.
   Файлы `works/` (~33 МБ) заливаются дольше остального — это нормально.
2. Убедитесь, что `.htaccess` перенёсся (он скрытый; в FileZilla: «Принудительный показ скрытых»).
3. Выставьте права (если нужно): `data` и `uploads` — `755` (или `775`).
4. Откройте `https://ваш-домен/` — главная должна загрузиться.
   База `data/site.sqlite` и таблицы создадутся автоматически при первом запросе
   (таблица работ заполнится файлами `works/work-*.jpg`).
5. Зайдите в `/admin`, пароль по умолчанию — **admin** (или значение `ADMIN_PASSWORD`).
   **Сразу** смените пароль в «Настройки».
6. Проверьте `/sitemap.xml`, `/robots.txt`, отправьте их в Яндекс.Вебмастер и Google Search Console.

## Локальный предпросмотр (по желанию, PHP локально)

```bash
php -c /path/to/php.ini -S 127.0.0.1:8090 -t php-site php-site/router.dev.php
```
`router.dev.php` нужен только для встроенного сервера PHP (он имитирует `.htaccess`);
на хостинг его можно не заливать, вреда не будет. OG-обложка пересоздаётся скриптом
`php php-site/scripts/make-og-cover.php` (нужен PHP с GD).

## Настройка через переменные окружения (SetEnv в .htaccess)

Пример — закомментированные строки в `.htaccess`. Раскомментируйте и подставьте:

```apache
SetEnv CONTACT_PHONE "+7 (863) 000-00-00"
SetEnv CONTACT_HOURS "Пн–Пт 08:00–18:00"
SetEnv YANDEX_METRIKA_ID "12345678"
SetEnv GA4_ID "G-XXXXXXXXXX"
SetEnv YANDEX_VERIFICATION "код-из-вебмастера"
SetEnv GOOGLE_VERIFICATION "код-из-search-console"
```

Телефон/часы по умолчанию пустые — блок не выводится, schema.org без телефона.
**Выдумывать номер нельзя — задайте реальный.**

## Что не перенесено из Next-версии (осознанно)

- **MAX-бот** (отправка заявок в мессенджер): в PHP-версии заявки копятся в админке.
  Если нужен бот — скажите, добавлю webhook-отправку (нужен токен бота).
- **Главный текст сайта** правится не через админку, а в `lib/content.php` (как в оригинале —
  дефолтные тексты в коде). Админка правит: оборудование, работы, заявки, пароль.
- Порядок/скрытие работ в галерее — через сортировку `sort_order` в БД (админка правит подписи,
  удаление и загрузку; точная перестановка drag&drop не переносилась).

## Проверка после загрузки

- `/sitemap.xml` — валидный XML со всеми URL
- `/robots.txt`, `/llms.txt` — открываются
- Форма на главной: отправка → запись в `/admin/submissions`
- `/admin` — вход, смена пароля
- Валидатор разметки Яндекса/Google:
  - Organization/LocalBusiness на всех страницах
  - FAQPage на `/voprosy` и на главной
  - Article на статьях блога

## Структура

```
php-site/
├── index.php          # front controller (маршрутизация)
├── .htaccess          # ЧПУ, защита data/lib/pages, заголовки, кеш
├── config.php         # SITE_URL, реквизиты, env (секреты сюда НЕ пишем)
├── lib/               # db, seo, render, content, equipment, faq, blog, admin
│   └── articles/      # 16 статей блога (файл = статья)
├── pages/             # страницы (*.php) + pages/partials/calculator.php
├── assets/            # style.css (оригинал) + site-ext.css + app.js + картинки
├── works/             # 71 фото портфолио
├── uploads/           # файлы из админки (создаётся автоматически)
└── data/              # site.sqlite (создаётся автоматически)
```

## Частые проблемы

- **«Не удалось создать каталог data/»** — дайте `data/` права на запись.
- **404 вместо ЧПУ** — у хостинга нет mod_rewrite или отключён `.htaccess`;
  включите AllowOverride, либо обратитесь в поддержку хостинга.
- **Кириллица-«крокозябры»** — файлы .php должны остаться в UTF-8 (они уже в UTF-8);
  не пересохраняйте их в Windows Notepad.
- **Сайт белый/500** — включите вывод ошибок или смотрите `php-error.log` в корне;
  чаще всего — нет расширения `pdo_sqlite`.
